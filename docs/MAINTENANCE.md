# 维护指南

本插件在 DSH 原生任务上增加模型选择，不实现第二套定时器。先复核目标版本的 npm 实际发布包，不把 GitHub `master` 文档当成已安装版本的契约。上游资料：[原生定时任务](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/schedule.md)、[模块导航](https://github.com/deepseek-ai/deepseek-harness/tree/master/packages/schedule)、[插件发布](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/develop/basic/publish.md)。

## 原生框架对照（以 v0.1.5 / DSH 0.2.2-rc.5 为基线）

| 链路 | DSH 负责 | 插件行为与边界 |
| --- | --- | --- |
| 创建与目录 | `schedule.create` 校验时间和目标；Session Controller 创建会话和关联工作区。 | `schedule_create_with_model` 先核对准确的模型/思考档位和目录，创建独立会话，再存一条原生任务；该会话后续复用。旧 `schedule_create_with_preset` 通过 `target.kind=new` 每次建新会话，保留 preset 和 cwd。两条路径的会话策略不同，不能悄悄互换。 |
| 规则与时间 | 绝对时间、间隔、日/周、cron、RRULE 等规则由 Host 计算，Host 停止时不运行。 | 自然语言创建支持一次、间隔、每日单点和每日多点。多点写成一条 RRULE；分钟不同时用 `BYSETPOS` 保留配对，不生成多余时刻。复杂周/月规则仍由原生编辑器或旧预设入口管理。浏览器显示时间可能和任务时区不同。 |
| 旧任务改模型 | 原生任务没有模型字段；原生 GUI 仍拥有任务的编辑、暂停、恢复、执行与删除。 | `schedule_update_model` 只接受调用会话可见的 `new` 目标，不改原生记录、目标、规则、目录、预设、状态或历史。对 `session`（含插件自己创建的独立复用会话）及 `new_once` 明确拒绝。GUI 新建的任务可能没有与当前对话的关联；仅有 ID 不等于可改。原生表单不会显示额外模型字段。 |
| 投递与重启 | Host 预留会话、投递并保存回执；共享会话的多条到期任务可以一起投递。 | 只在已有覆盖配置且匹配 Host 预留会话时，借助 `schedule/resolve-agent` 选择并持久化模型，再让 Host 投递。覆盖配置按任务 ID 存在插件自己的 profile 目录，**不在原生任务里**；停用或卸载插件后不要假定原有覆盖依然生效。Profile 搬迁和回退要考虑原生任务、会话数据与覆盖文件三者。 |
| 查询与作用域 | 回执指向投递消息；模型请求日志记录请求配置。 | 查询区分配置、历史中的实际 DSH 请求和供应商最终选用的模型。没有证据时返回未核验，不用配置值冒充实跑。查询、更改只限关联会话，子代理拒绝；原生工具的系统范围不因本插件扩大。 |

### v0.1.6：启动期 briefing 兼容与失败恢复

- 保留原生预留逻辑与 `schedule/resolve-agent`。rc.5 新会话的首次激活会直接走创建路径；插件在 native activation 完成后、调度提示词入队前核对 turn 边界与持久化。如果只有启动插件排入的 `next-step` briefing，它不是已开始的 turn。仍保留 `next-turn`、活跃状态和已打开/完成 turn 的保护，不篡改已有会话路线。
- 若真正开始的会话已有不同路线，保留当前模型完成该次投递，查询显示 `lastSkipped.status=kept_existing_route`。配置损坏、模型不可用、选择或持久化失败则不向其他服务商发送任务内容；原生投递仍待处理，查询报告 `blocked_before_delivery`。修正配置或在原对话明确撤销覆盖，再重试。没有上一笔回执时 `latestRun.status=pending_delivery`；若有上一笔，保留历史请求，并单列本次 `pending`。
- `schedule_clear_model` 只清理这个任务自己的覆盖，恢复随后投递的原预设或默认，不更改已跑历史。覆盖仍按 profile 保存，Windows 的 POSIX mode 不等于访问控制；请由 profile 所在目录的 ACL 保护。暂不自动回收任务删除后的孤儿文件，直到跨 profile 的原生视图和文件所有权都验证清楚。
- `providerReturnedModel:null` 表示 DSH 没有给插件可验证的上游返回模型。不会扫描外部网关的日志或据此猜测。任务查询里 `configuredSource` 的取值是 `override`、`preset`、`session` 和 `native_or_unknown`。

### 跨工作区管理会话

- 普通查询/修改的同会话范围保持不变。跨会话功能需要本地 profile 明确配置 `managementPreset`、当前 Agent 使用该配置指向的预设、具有对应原生管理工具、存在活跃 owner 客户端，且当前调用得到原生 `allowed-once` 审批。加载受信任 Host 插件是必要前提：其他已安装 Host 插件能够参与审批 answerer，不把这当作对不受信任 Host 的安全边界。
- 审批后的模型查询输出最少信息：任务标题、标识、目标种类、配置、状态及工作区分组；不输出提示词、完整路径或对话日志。工作区采用 Native registry 的执行目标，不猜来源。目录或注册信息不可读时返回未知。
- 批量写入绑定审批时的任务和模型，审批后复核原生条目与覆盖值；单任务插件写入串行化，但不是跨任务事务，也不能锁住 Native 编辑器。部分成功会逐条返回，不自动重试或改任务目标。默认网关当前模型只单独展示，不是假定的任务请求。
- 复用会话上的多个原生任务可能共用同一轮和一个模型请求，不入批量写入。不要用原生 GUI 保存修改来给某个对话制造归属，也不要临时改接收会话的全局模型。

### 最脆弱的接口

- `schedule/resolve-agent` 是活跃会话恢复钩子，入参**只有会话 ID**。本插件从 `storageDomain.get('schedule').table('tasks')` **只读**诊断视图核对 `pendingDelivery.targetSessionId`。表结构、预留写入时序、钩子顺序不是独立的稳定插件 API。升级前逐项重验。不要用标题、提示词、最近运行会话猜映射；不要写原生表、篡改原生任务或降级默认模型来掩盖不匹配。
- 复查 Agent 是否仍在首条输入前允许 `agent.model.select`、持久化回执是否仍可靠、关联权限及日志事件是否变化。保留旧 preset 路由行为，并验证同 preset 的无覆盖任务不受影响。只保留 preset 不能证明该 preset 的所有工具都正常，需要真实 preset 回归。
- 一旦宿主不再提供可靠关联，停止为该宿主版本发布；优先寻求原生“按任务指定模型”或带任务 ID 的投递 API，而不是加隐式绕路。

## 改动与发布

1. 写下受影响的入口、调用方和持久化兼容要求。用干净 profile 与升级 profile 分测，不在用户 profile、工作电脑或真实模型上跑回归。不删除现有功能、不绕过校验、不用旧截图充当新一版 GUI。
2. 按[测试指南](TESTING.md)运行：单测、实际 Host、GUI。对新版优先实测最低可用版和当前官方发布版；声明允许的版本不等于已测过。发现不兼容只收窄范围或做可验证的修复，不只修改版本字符串。
3. 运行时代码发布前打包并记录 SHA-256，验证 Git 与本地包安装实际加载的版本。保留旧包；不是每次文档测试改动都重打包。功能和 GUI 都通过后才 fast-forward 推送，推完核对远端 commit 和安装。市场送审是另一件事。
4. 记录版本、平台、Git/包安装方式、结果和未测项。若安装、周期、路由或恢复失败，先停止推广并保留证据；不要删除旧任务、会话历史或覆盖文件。回退代码前如需停止模型覆盖，先暂停受影响任务，确认重新启用后的实际模型。

## 审核发现与后续优先级

1. **高：模型覆盖和原生任务的存储范围不同。** rc.5 上已实测：卸载插件后，原生任务仍在，同一 profile 重启后按原生默认模型运行；原覆盖未生效。覆盖记录按 profile 存放。跨 profile 的测试结果不充分，不能推断默认或自定义 profile 的共享行为；共享存储和迁移仍须单独验证。卸载、停用、回退及迁移前先暂停依赖覆盖的任务。
2. **高：当前对话不是原生 GUI 的全局权限。** 插件新建的独立复用任务暂不能用更新工具改模型；GUI 建的任务也未必与当前对话关联。应补原生任务绑定/授权方案及安全的复用策略，不能放宽到所有任务或改执行目标来掩盖问题。
3. **高：创建没有跨会话和任务的统一事务。** 语法正确但已过期的单次时间等可能在 Host 拒绝任务时留下刚建的空会话。后续用上游校验或可证明安全的清理，另测中途取消、写盘失败及任务列表/会话列表均不残留。只请求修改思考等级时，也不能把遗漏的模型当成换模型许可。
4. **中：测试不能代替支持承诺。** 已用模拟模型验证同 profile 恢复和独立任务隔离；尚未证明 Windows/Desktop、真实服务商、SDK 或同时运行多个 profile 的行为。查询只读有限历史，旧请求可能返回未核验；不能回填成“实跑成功”。
